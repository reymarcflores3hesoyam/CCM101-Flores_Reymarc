# Mission 4 Reflection

Laboratory 04 helped me understand Docker and containerization through actual practice. I learned that containers are lighter and faster to start compared with Virtual Machines because they do not need a complete guest operating system for every application. In this activity, I used the KillerCoda Ubuntu environment and checked Docker using `docker --version` and `docker info`. I then pulled the Nginx image using `docker pull nginx` and created the Nginx container using `docker run`. This showed me that a container can be prepared and started with only a few commands, making the setup process simpler than installing an operating system on a Virtual Machine.

I also learned why port mapping is important when running a web server inside a container. The `-p 8080:80` option connects port 8080 of the host to port 80 inside the Nginx container. I tested the web server using `curl http://localhost:8080` and successfully received the Nginx welcome page. After testing Nginx, I practiced the container lifecycle by using `docker ps`, `docker stop nginx-server`, `docker ps`, `docker rm nginx-server`, and `docker ps -a`. I learned that `docker rm` removes the stopped container, and data stored only inside the container may not remain after it is removed.

This activity also helped me understand how containerization can support DevOps. Developers can prepare applications in containers, while IT operations teams can use the same container for deployment. This can make the application environment more consistent and easier to manage. I also improved my GitHub portfolio by creating the Laboratory 04 folder, Markdown files, and a screenshots folder for my Docker evidence. Overall, I gained practical skills in Docker, Nginx deployment, port mapping, container lifecycle management, Markdown documentation, and GitHub organization. The activity helped me connect cloud computing concepts with actual technical practice.
