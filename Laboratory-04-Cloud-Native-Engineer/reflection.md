**Mission 4 Reflection**

Through hands-on practice, Lab 04 gave me direct experience with Docker and containerization. I saw firsthand that containers are much lighter and spin up far faster than Virtual Machines since they don't carry the bulk of a full guest operating system. Working in the KillerCoda Ubuntu environment, I checked my setup using `docker --version` and `docker info`, pulled the Nginx image with `docker pull nginx`, and launched it using `docker run`. Seeing an Nginx container start in seconds with just a few terminal commands made it clear how much easier container setup is compared to installing an OS on a VM.

Understanding port mapping was another major key. Using the `-p 8080:80` flag, I bridged host port 8080 to port 80 inside the container. Testing this with `curl http://localhost:8080` brought up the standard Nginx welcome page, confirming the server was live. I then explored the container lifecycle using `docker ps`, `docker stop nginx-server`, `docker rm nginx-server`, and `docker ps -a`. This showed me that once a container is deleted via `docker rm`, any unbacked data inside it disappears—highlighting the importance of ephemeral design.

Finally, this lab bridged core DevOps concepts with actual practice. Containers guarantee consistency across environments, allowing developers and ops teams to run identical setups without deployment headaches. On the documentation front, I updated my GitHub portfolio by organizing my Lab 04 directory with Markdown reports and screenshots. Overall, I gained valuable, real-world skills in Docker execution, port forwarding, container management, and technical documentation.
